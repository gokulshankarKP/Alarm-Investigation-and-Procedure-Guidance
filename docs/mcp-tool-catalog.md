# MCP tool catalog: `alarm-management` server

_Generated by `python scripts/generate_tool_catalog.py` from the live tool definitions; example responses are real calls against the simulator (shortened)._

## Common behaviour (all tools)

| Aspect | Behaviour |
|---|---|
| Transport | Streamable HTTP at `http://<host>:9000/mcp` (stateless, JSON responses) or stdio (`python -m alarm_mcp --transport stdio`). |
| Client authentication | `Authorization: Bearer $MCP_AUTH_TOKEN` required on `/mcp` (401 otherwise). `/health` is public. |
| Upstream authentication | The server calls the Alarm API with `Authorization: Bearer $ALARM_API_TOKEN`. That token never leaves the server and is redacted from logs. |
| Trace metadata | Client headers `x-trace-id` / `x-conversation-id` are forwarded as `trace_id` / `x-trace-id`, `x-client-id: alarm-mcp-server` and `x-metadata-tag: mcp-tool:<tool>;conversation:<id>`. A trace id is generated when absent. Every result carries `meta.trace_id`. |
| Input validation | JSON-schema from typed signatures (types, enums, min/max, id pattern `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$`) plus semantic checks (start < end, max 400-day range, scope required). |
| Output validation | Upstream payloads are validated against the output schema. A mismatch returns `UPSTREAM_CONTRACT_ERROR`. |
| Timeout / retry | Per API call `ALARM_API_TIMEOUT_S` (default 10 s). Retries `ALARM_API_MAX_RETRIES` (default 2) on 429/502/503/504, timeouts and connection errors, with exponential backoff and jitter, honouring `Retry-After`. Retries are reported in `meta.api_calls[].retries`. |
| Errors | Tool errors (`isError: true`) carry JSON `{"error": {code, message, status_code, retryable, attempts, trace_id, tool, endpoint, details}}`. Codes: `INVALID_ARGUMENT`, `NOT_FOUND`, `UNAUTHORIZED`, `RATE_LIMITED`, `UPSTREAM_UNAVAILABLE`, `UPSTREAM_TIMEOUT`, `UPSTREAM_CONTRACT_ERROR`. |
| Annotations | All tools are `readOnlyHint: true`, `idempotentHint: true`, `destructiveHint: false`. There are no write operations. |

### `get_alarms`

**Purpose:** Retrieve active or historical alarms with filters and pagination. At least one of asset_ids, site, unit or alarm_code is required. Use status='active' for current alarms.

**Underlying operation:** `GET /alarms (page/page_size; optional multi-page fetch)`

**Input schema**

| Parameter | Type | Required | Constraints / default | Description |
|---|---|---|---|---|
| `asset_ids` | array \| null | no | default=null | Asset identifiers, e.g. ['BFP-101'] |
| `site` | string \| null | no | default=null | Site, e.g. 'NorthPlant' |
| `unit` | string \| null | no | default=null | Unit, e.g. 'Unit 1' |

| `end_time` | string \| null | no | default=null | Only alarms starting before this time |

| `sort_order` | string enum ['asc', 'desc'] | no | default="desc" |  |
| `page` | integer | no | minimum=1, default=1 |  |
